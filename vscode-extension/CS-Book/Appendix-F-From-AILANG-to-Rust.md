# Appendix F: From AILANG to Rust

This appendix provides a conceptual mapping between AILang and Rust for readers who know (or are learning) Rust. The goal is to highlight where the mental models are similar and where they differ significantly.

## Core Philosophical Difference

- **Rust** uses a sophisticated type system (borrow checker, ownership, lifetimes) to *prevent* many classes of bugs at compile time while still giving high performance and low-level control.
- **AILANG** uses radical explicitness and named operations so that the programmer (and AI coding agents) can *see* what is happening at the machine level. Safety comes more from visibility and discipline than from static enforcement in all cases.

Both approaches reject "type this and pray" programming. They just enforce clarity in very different ways.

## Key Concept Mappings

| Concept                    | Rust                                      | AILANG                                              | Notes |
|---------------------------|-------------------------------------------|-----------------------------------------------------|-------|
| Ownership                 | `let x = ...; let y = x;` moves           | Explicit via pools and manual discipline            | AILANG has no automatic move semantics |
| Borrowing                 | `&T` and `&mut T`                         | Not directly present; use LinkagePool `Direction=` (Input/Output/InOut) on fields or FixedPool | AILANG makes aliasing explicit via addresses and explicit contracts |
| Lifetimes                 | `'a`, `&'a T`                             | Not expressed in the type system                    | Lifetimes are managed via explicit allocation/deallocation and pool design |
| Smart pointers            | `Box<T>`, `Rc<T>`, `Arc<T>`               | Manual use of `Allocate` + `LinkagePool` or raw pointers | No automatic reference counting in core AILANG |
| Error handling            | `Result<T, E>`, `?` operator              | Sentinel returns + `TryBlock` / `CatchError`        | Very different ergonomics |
| Unsafe code               | `unsafe { ... }` blocks                   | No equivalent keyword — low-level operations are just explicit functions | AILANG makes "unsafe" operations visible by name |
| Stack vs Heap             | Mostly implicit (locals on stack)         | Explicit: locals are on stack, everything else uses `Allocate` or pools | Much more visible in AILANG |
| Structs / Records         | `struct Point { x: i32, y: i32 }`         | `LinkagePool.Point { "x": ..., "y": ... }`         | AILANG records are always heap-allocated by default |

## Mental Model Shifts When Moving Between the Languages

**From Rust to AILANG:**
- You will lose the borrow checker as a safety net.
- You will gain much clearer visibility into what the machine is actually doing (especially memory, function calls, and data movement).
- You will write more characters, but the resulting code is often easier for humans and AI agents to reason about precisely.

**From AILANG to Rust:**
- You will gain powerful static guarantees (especially around aliasing and lifetimes).
- You will lose some of the direct "this compiles to these exact instructions" transparency.
- You will need to internalize the borrow checker rules, which can feel magical at first if you are used to fully explicit memory management.

## When to Choose Which Language

- Choose **AILANG** when you want (or need) maximum visibility into the machine, when you are teaching computer science from the ground up, or when you are building systems where the ability for humans and AI agents to understand the code is paramount.
- Choose **Rust** when you want strong compile-time memory safety guarantees without a garbage collector, especially for large teams or long-lived production systems where certain classes of bugs must be impossible.

Many concepts transfer well in both directions (explicit thinking about memory, careful API design, performance awareness), even though the surface syntax and enforcement mechanisms differ dramatically.

For the most accurate mapping when porting code, always look at the actual machine code generated by both compilers for the same algorithm. The AILANG compiler is deliberately designed to make its output readable for exactly this kind of comparison.
